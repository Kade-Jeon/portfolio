주요 업무

크리니티에서 Java/JSP 메일 서비스의 기능 개발과 운영을 맡았습니다. 고객사 문의 대응 외에 외부 API 연동, 검색 기능 개선, 로그 모니터링 구축, Spring AI PoC 개발이 주요 업무였습니다.

고객사 문의 재현과 수정

고객사 13곳의 문의를 맡았습니다. 기관마다 쓰는 기능과 환경이 달라 같은 증상이라도 원인이 다른 경우가 많아서, 먼저 문의를 재현한 뒤 원인을 좁혔습니다.

  • 재현 후 로그와 코드로 원인 확인
  • 고객사별 반영과 제품 공통 수정 구분
  • 반복되는 문의는 레거시 코드까지 수정

Lucene 검색에 결과 내 재검색 추가

레거시 Lucene 검색 엔진은 바꾸기 어려운 구조여서, 엔진은 그대로 두고 검색 흐름만 확장했습니다.

  • 1차 검색 결과 mailUid와 재검색 결과의 교집합으로 구현
  • 결과 내 재검색 최대 5회
  • 기존 검색 코드 변경 범위 최소화

외부 API 호출 구조 정리

확장하기 어려운 호출 구조는 새 기능을 붙이기 전에 먼저 정리했습니다. 자세한 내용은 아래 프로젝트 사례에 있습니다.

  • shell curl로 호출하던 통신사 API를 Java RestTemplate으로 재작성
  • 단일 프롬프트 호출 AI 기능을 Spring AI ChatClient 기반으로 전환
  • 공통 처리와 타입별 처리 분리

API 연동

농식품공사 SMS를 MMS로 확장

한국농수산식품유통공사 요청으로 기존 SMS 기능을 MMS까지 확장했습니다. curl 방식으로 호출하던 통신사 API는 Java RestTemplate으로 다시 작성했습니다.

  • 통신사 API 호출부 RestTemplate 재작성
  • SMS/MMS 공통 처리와 타입별 처리 분리
  • 엑셀 대량 발송을 수신자 제한 단위로 나눠 병렬 발송
  • 발송 결과 집계

모니터링

KISTI 로그 모니터링 구축

KISTI 프라이빗 클라우드에서는 문의가 오면 VM마다 접속해 로그를 확인해야 했습니다. Docker로 ELK와 Elastic APM을 구성해 Kibana에서 로그를 한 번에 조회하게 했고, 느린 쿼리까지 개선해 문의 대응 시간을 약 30% 줄였습니다.

  • Docker 기반 ELK, Elastic APM 구성
  • Fleet, Elastic Agent로 서버와 애플리케이션 로그 수집
  • APM Slow Query로 찾은 불필요한 메일 조회 조건 제거
  • Kibana 권한 Admin, Readonly 분리

AI PoC

메일 서비스 Spring AI PoC

기존 AI 기능은 RestTemplate으로 프롬프트를 한 번 보내는 구조라 기능을 늘리기 어려웠습니다. Spring AI ChatClient 기반으로 구조를 바꾸고 메일 AI 기능 4개를 직접 구현했습니다.

  • 다국어 번역, 초안 작성, 메일 요약, 첨부파일 요약
  • AI 서버는 별도 운영
  • AI × Softwave 2025(2025.12, 코엑스)에서 G-Cloud 공공메일 AI 기능으로 시연
  • NIA(한국지능정보사회진흥원)에 베타 도입
