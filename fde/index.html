왜 Forward Deployed Engineer인가

CS·요구사항 대응에서 출발해 제품 개선으로 이어가는 경로를 밟아 왔습니다. 고객 앞단의 문제를 이해하고, 이해관계자를 조율하며, PoC를 실제 도입까지 밀어붙인 경험이 FDE 역할과 맞닿아 있습니다.

CS → 제품 개선

크리니티에서 고객사 13개 CS 채널을 대응하며 운영 이슈 원인을 분석했습니다. 단순 티켓 처리에 그치지 않고, 반복되는 문제를 기능·구조 개선 과제로 전환했습니다.

  • 고객사별 요구사항·버그·예외 케이스 반영
  • 레거시 검색·외부 API 등 구조적 병목 개선

이해관계자 조율 (영업 경력)

한국학술정보 솔루션영업, 다다무역 해외영업으로 약 4년간 B2B 고객·생산처·유관부서 사이의 요구사항을 정리하고 일정을 조율했습니다.

  • 공공·대학·연구기관 고객 문의/요구사항 대응
  • 개발·디자인·CS와 협업해 서비스 개선 진행

PoC → NIA 도입

Spring AI 기반 공공 메일 AI 기능 PoC를 설계·구현했고, G-Cloud 공공 클라우드 메일 AI 기능 PoC로 채택되어 한국지능정보사회진흥원(NIA) 베타 운영 환경에 도입되었습니다.

  • RestTemplate 단일 프롬프트 한계를 ChatClient 구조로 전환
  • RAG·에이전트·Langfuse 확장 가능 구조 설계

관측성 · 운영 구조 개선

KISTI 프라이빗 클라우드에 ELK/Fleet/APM을 구축해 VM별 root 접속 로그 확인에서 Kibana 중앙 조회로 전환했습니다. 장애·CS 대응 시간을 기존 대비 약 30% 수준으로 단축했습니다.

  • Admin/Readonly 권한 분리로 로그 접근 보안 개선
  • APM Slow Query로 SQL 조건 개선

현장 전달을 뒷받침하는 근거

고객 접점, 해외 커뮤니케이션, 도입까지의 실행력을 이력 기준으로 정리했습니다.
